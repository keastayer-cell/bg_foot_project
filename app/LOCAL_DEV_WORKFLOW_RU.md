# Локальный цикл работы: backend + web

Этот файл описывает нормальный локальный сценарий работы с проектом после правок, чтобы быстро:

- перезапускать backend
- перезапускать frontend
- проверять, что оба сервиса действительно поднялись
- тестировать изменения без ручной путаницы с портами и процессами

Файл ориентирован на два проекта:

- backend: `/Users/korytov/projects/football-stats-app`
- frontend: `/Users/korytov/projects/football-stats-web`

## Какие адреса считаем рабочими

- backend health: `http://127.0.0.1:8080/api/health`
- frontend dev: `http://127.0.0.1:4173/`

Нормальная цель локальной разработки:

- backend всегда на `8080`
- frontend всегда на `4173`

Если frontend внезапно ушел на `4174`, `4175` и так далее, это значит, что старый процесс не был корректно остановлен или dev-сервер запустили без жесткой фиксации порта.

## Самый удобный способ: через VS Code tasks

Сейчас для обоих проектов уже созданы задачи VS Code.

Где они лежат:

- backend tasks: `/Users/korytov/projects/football-stats-app/.vscode/tasks.json`
- frontend tasks: `/Users/korytov/projects/football-stats-web/.vscode/tasks.json`

Как их запускать:

1. Открой `Terminal -> Run Task`
2. Или нажми `Cmd+Shift+P`
3. Выполни `Tasks: Run Task`
4. Выбери нужную задачу

Доступные задачи backend:

- `Restart Backend (8080)`
- `Rebuild + Restart Backend (8080)`

Доступные задачи frontend:

- `Restart Web Dev (4173)`
- `Build + Preview Web (4173)`

Что делают эти задачи:

- находят все процессы на целевом порту
- завершают их
- поднимают проект заново

Это и есть основной сценарий, который нужно использовать после моих правок.

## Рекомендуемый рабочий порядок после изменений

Если я менял только frontend:

1. Запусти задачу `Restart Web Dev (4173)`
2. Открой `http://127.0.0.1:4173/`
3. Проверь нужный экран

Если я менял только backend:

1. Запусти задачу `Restart Backend (8080)`
2. Открой `http://127.0.0.1:8080/api/health`
3. Убедись, что пришел ответ `{"status":"UP","service":"football-stats-app"}`
4. Потом обнови frontend в браузере

Если я менял и backend, и frontend:

1. Сначала запусти `Restart Backend (8080)`
2. Дождись, пока backend реально поднимется
3. Потом запусти `Restart Web Dev (4173)`
4. Открой frontend на `http://127.0.0.1:4173/`
5. Проверь целевой сценарий в интерфейсе

Почему backend лучше поднимать первым:

- frontend может загрузиться быстрее backend
- из-за этого UI иногда показывает пустые данные, ошибки загрузки или странные состояния
- если backend уже стабильно поднят, проверка UI становится предсказуемой

## Что запускать в обычной разработке

Для backend в обычной работе нужен:

- `Restart Backend (8080)`

Для frontend в обычной работе нужен:

- `Restart Web Dev (4173)`

Этого достаточно почти всегда.

## Когда использовать полную пересборку backend

Задача:

- `Rebuild + Restart Backend (8080)`

Использовать ее стоит, если:

- менялись зависимости в `pom.xml`
- менялась конфигурация запуска
- появились странные эффекты после предыдущего старта
- есть ощущение, что обычный `spring-boot:run` поднял старое состояние

Эта задача делает:

1. остановку процессов на `8080`
2. `mvn clean package`
3. `mvn spring-boot:run`

Она медленнее обычного restart, но надежнее в спорных случаях.

## Когда использовать build + preview для frontend

Задача:

- `Build + Preview Web (4173)`

Ее не нужно использовать после каждой правки.

Она нужна только когда нужно проверить именно production-вариант frontend:

- как собирается `dist`
- нет ли ошибок только в production-сборке
- как выглядит уже собранная версия

Для повседневной разработки эта задача лишняя. Основная рабочая задача для нас:

- `Restart Web Dev (4173)`

## Ручной запуск без VS Code tasks

Если по какой-то причине нужно поднять все руками, используй именно такой порядок.

### Backend вручную

```bash
cd /Users/korytov/projects/football-stats-app
pids=$(lsof -ti :8080)
if [[ -n "$pids" ]]; then print -r -- "$pids" | xargs kill -9; fi
mvn spring-boot:run
```

Полная пересборка backend вручную:

```bash
cd /Users/korytov/projects/football-stats-app
pids=$(lsof -ti :8080)
if [[ -n "$pids" ]]; then print -r -- "$pids" | xargs kill -9; fi
mvn clean package
mvn spring-boot:run
```

### Frontend вручную

```bash
cd /Users/korytov/projects/football-stats-web
pids=$(lsof -ti :4173)
if [[ -n "$pids" ]]; then print -r -- "$pids" | xargs kill -9; fi
npm run dev -- --host 127.0.0.1 --port 4173 --strictPort
```

Production preview вручную:

```bash

if [[ -n "$pids" ]]; then print -r -- "$pids" | xargs kill -9; fi
npm run build

```

## Как проверить, что backend точно поднялся

Минимальная проверка:

```bash
curl http://127.0.0.1:8080/api/health
```

Ожидаемый ответ:

```json
{"status":"UP","service":"football-stats-app"}
```

Также в логах backend нормальный признак такой:

- есть строка `Tomcat started on port 8080`
- есть строка `Started FootballStatsBackendApplication`

Если этого нет, значит backend либо еще не поднялся, либо упал при старте.

## Как проверить, что frontend точно поднялся

Признаки нормального старта:

- в терминале есть `VITE ready`
- в терминале показан адрес `http://127.0.0.1:4173/`
- страница открывается в браузере

Если Vite пишет, что порт занят, а ты запускал без `--strictPort`, он может молча уйти на другой порт. Поэтому для стабильной локальной работы мы используем именно:

```bash
npm run dev -- --host 127.0.0.1 --port 4173 --strictPort
```

## Что делать, если все сломалось

Самый безопасный сценарий восстановления:

1. Останови frontend-задачу
2. Останови backend-задачу
3. Запусти `Restart Backend (8080)`
4. Дождись health-check `UP`
5. Запусти `Restart Web Dev (4173)`
6. Обнови страницу в браузере

Если не помогло, следующий шаг:

1. Запусти `Rebuild + Restart Backend (8080)`
2. Затем снова `Restart Web Dev (4173)`

## Что делать, если порт уже занят

### Backend

Проверка:

```bash
lsof -i :8080
```

Очистка:

```bash
pids=$(lsof -ti :8080)
if [[ -n "$pids" ]]; then print -r -- "$pids" | xargs kill -9; fi
```

### Frontend

Проверка:

```bash
lsof -i :4173
```

Очистка:

```bash
pids=$(lsof -ti :4173)
if [[ -n "$pids" ]]; then print -r -- "$pids" | xargs kill -9; fi
```

Важно: иногда на одном порту висит несколько PID. Именно поэтому нельзя полагаться на простое `kill -9 $pid`, если в переменной несколько строк. Нужно завершать их через `xargs`.

## Что означают текущие задачи

### `Restart Backend (8080)`

Использовать почти всегда после backend-правок.

### `Rebuild + Restart Backend (8080)`

Использовать после изменения зависимостей, конфигурации или если обычный запуск ведет себя подозрительно.

### `Restart Web Dev (4173)`

Основная задача для всех UI-правок.

### `Build + Preview Web (4173)`

Использовать только если нужно проверить production-сборку frontend.

## Нормальный ежедневный сценарий для нашей работы

После моих правок придерживаемся такого алгоритма:

1. Я вношу изменения в код
2. Если менялся backend, запускаем `Restart Backend (8080)`
3. Если менялся frontend, запускаем `Restart Web Dev (4173)`
4. Проверяем `http://127.0.0.1:8080/api/health`
5. Проверяем `http://127.0.0.1:4173/`
6. Тестируем конкретный пользовательский сценарий

Если изменения только во frontend, backend можно не трогать.

Если изменения только в backend, frontend обычно не нужно перезапускать, достаточно обновить страницу. Но если на экране есть сложная форма, кешированное состояние или старая вкладка, проще все равно перезапустить и web тоже.

## Что важно помнить

- для обычной работы нужен `dev`, а не `preview`
- backend удобнее поднимать первым
- фиксированные порты уменьшают путаницу
- если сервис не отвечает, сначала проверь порт и лог запуска
- если что-то выглядит странно, safest path: restart backend, потом restart web

## Короткая памятка

Если нужно быстро восстановиться после правок:

1. `Restart Backend (8080)`
2. проверить `http://127.0.0.1:8080/api/health`
3. `Restart Web Dev (4173)`
4. открыть `http://127.0.0.1:4173/`

Это и есть основной локальный цикл, на который дальше можно опираться в работе.
