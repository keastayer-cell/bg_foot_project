# Этап 4. Укрепление backend

Дата выполнения: 2026-07-27.

## Границы и транзакции

- Бизнес-операции игроков и судей перенесены из контроллеров в `PlayerManagementService` и `RefereeManagementService`.
- Чтение составов и трансферов сезона вынесено из `SeasonController` в `SeasonQueryService`.
- Контроллеры больше не открывают транзакции и не работают с репозиториями игроков, судей и сезонных проекций напрямую.
- Читающие сервисные методы помечены `readOnly = true`, изменения выполняются в write-транзакциях.
- Ротация refresh-token использует `PESSIMISTIC_WRITE`, поэтому один токен нельзя успешно обменять параллельно дважды.
- Решения по сезонной заявке и трансферу используют locked-загрузку. Проверка текущего статуса внутри той же транзакции делает повторное approve/reject/revoke идемпотентно безопасным: повтор не выполняет бизнес-операцию второй раз.
- Индекс `ux_w_season_transfer_request_blocking_player` запрещает конкурирующие заявки в статусах `PENDING`/`APPROVED`, включая гонку создания с approve.

## Ошибки и DTO

Все MVC и security ошибки используют envelope:

```json
{
  "timestamp": "2026-07-27T20:00:00Z",
  "status": 400,
  "error": "Описание ошибки",
  "path": "/api/example",
  "fieldErrors": {}
}
```

Поле `error` сохранено для совместимости frontend. Неожиданные исключения логируются на сервере, клиент получает нейтральный текст без внутренних данных. DTO игроков, судей, команд, сезонов, матчей, составов и лиги получили ограничения обязательности, размера и неотрицательных чисел.

## N+1

- Игроки: активные команды, сезонные назначения и фото загружаются тремя пакетными запросами на страницу вместо запросов на каждого игрока.
- Судьи: фото списка загружаются одним запросом.
- Команды: фото сезонного состава загружаются одним запросом.
- Заявки: число игроков считается одним `GROUP BY`, фото состава загружаются пакетно.
- Трансферы и сезонные составы: связанные сущности загружаются fetch-query, фото пакетно.
- Матчи и таблицы уже использовали `JOIN FETCH` для тура, сезона, команд и протокола; поэлементных repository-вызовов в расчёте таблицы нет.

## Проверки

- Unit-тест фиксирует пакетную загрузку списка игроков.
- Тесты refresh-token, сезонных заявок и трансферов проверяют использование locked-загрузки.
- Тест error handler проверяет стабильный envelope и отсутствие утечки внутреннего сообщения.
- Полный backend test suite и package выполняются перед фиксацией этапа.
