# Замечания по проекту

Этот файл хранит найденные технические замечания, которые ещё требуют решения или отдельного решения владельца проекта.

Статусы:

- `ОТКРЫТО` - замечание подтверждено, работа ещё не выполнена;
- `В РАБОТЕ` - исправление начато;
- `ИСПРАВЛЕНО` - изменение реализовано и проверено;
- `ПРИНЯТО` - риск осознанно принят без изменения кода.

При закрытии пункта исходная дата обнаружения сохраняется, а рядом добавляются дата решения, коммит и результат проверки.

## 28.07.2026

### Локальный backend не находит корневой `.env` без явного пути

- Статус: `ОТКРЫТО`
- Важность: средняя
- Обнаружено: при локальном запуске проекта после чистой синхронизации с `dev`.
- Наблюдение: команда `mvn -f app/pom.xml spring-boot:run` запускает приложение с рабочей директорией `app`, поэтому значение по умолчанию `.env` ищется внутри `app`, а не в корне репозитория. Backend завершается с ошибкой обязательного `JWT_SECRET`.
- Временное решение: запускать с `BG_FOOT_ENV_FILE="$PWD/.env"`.
- Предлагаемое действие: исправить локальную команду запуска и документацию либо настроить Maven/Spring так, чтобы корневой `.env` находился автоматически и одинаково для backend и mailer.

### В npm-зависимостях есть известные уязвимости

- Статус: `ОТКРЫТО`
- Важность: высокая
- Обнаружено: `npm --prefix web ci` сообщил о 10 уязвимостях: 3 умеренных, 6 высоких и 1 критической.
- Наблюдение: автоматический `npm audit fix --force` не применялся, поскольку он может обновить зависимости с несовместимыми изменениями.
- Предлагаемое действие: изучить `npm audit`, отделить runtime-зависимости от dev-зависимостей, обновить пакеты контролируемо и повторить lint, unit, e2e и production build.

### Локальная версия PostgreSQL новее проверенной версии Flyway

- Статус: `ОТКРЫТО`
- Важность: низкая
- Обнаружено: при применении миграций к локальному PostgreSQL 17.10.
- Наблюдение: используемая версия Flyway сообщает, что протестирована до PostgreSQL 16. Все 54 миграции при этом успешно применились.
- Предлагаемое действие: для воспроизводимой разработки использовать PostgreSQL 16, как в CI, либо обновить Flyway после проверки совместимости.

### Исходное изображение заметно увеличивает frontend-сборку

- Статус: `ОТКРЫТО`
- Важность: средняя
- Обнаружено: при `npm --prefix web run build`.
- Наблюдение: файл `Screenshot at Apr 28 20-18-16.png` занимает около 2,58 МБ в production bundle.

### Нет отдельного live E2E-набора для полного локального стека

- Статус: `ОТКРЫТО`
- Важность: средняя
- Обнаружено: при добавлении визуальных режимов запуска Playwright.
- Наблюдение: текущие 5 smoke-сценариев проверяют frontend с перехваченными API-ответами. Они не проверяют совместную работу frontend, backend, Flyway и PostgreSQL.
- Предлагаемое действие: создать отдельный live-набор с изолированной тестовой БД, предсказуемыми пользователями разных ролей, seed/cleanup-процедурой и явной защитой от запуска на test/prod.

### Настоящий мобильный браузер получает desktop viewport

- Статус: `ОТКРЫТО`
- Важность: высокая
- Обнаружено: при визуальном аудите с полным профилем iPhone 13.
- Наблюдение: в `web/index.html` отсутствует `<meta name="viewport">`. В эмуляции iPhone значение `window.innerWidth` равно 980 при физической ширине 390, поэтому мобильные media queries не срабатывают и desktop-страница масштабируется целиком.
- Предлагаемое действие: добавить корректный viewport meta, затем повторить визуальные и E2E-проверки на ширинах 320, 360, 390, 430, 768 и 1024 пикселя.

### Поля поиска растягиваются по высоте на мобильной ширине

- Статус: `ОТКРЫТО`
- Важность: высокая
- Обнаружено: на страницах `Игроки` и `Команды` при viewport 390 пикселей.
- Наблюдение: после переключения фильтра во `flex-direction: column` значение `flex: 1 1 320px` начинает задавать высоту поля. Измеренная высота input составляет 320 пикселей.
- Предлагаемое действие: в мобильном media query сбросить flex-basis (`flex: 0 0 auto`) и добавить regression-проверку высоты фильтров.

### Имена игроков имеют слишком маленькую область нажатия

- Статус: `ОТКРЫТО`
- Важность: средняя
- Обнаружено: при измерении интерактивных элементов на странице `Игроки`.
- Наблюдение: кнопки с именами имеют высоту около 18 пикселей. Попасть по ним пальцем заметно сложнее рекомендуемой области не менее 44 на 44 пикселя.
- Предлагаемое действие: сделать кликабельной всю строку игрока или добавить кнопке минимальную высоту и горизонтальный padding.

### Мобильная навигация перегружается после авторизации

- Статус: `ОТКРЫТО`
- Важность: средняя
- Обнаружено: при проверке роли `SUPER_ADMIN` на ширине 390 пикселей.
- Наблюдение: семь пунктов глобального меню занимают несколько строк, а стартовая админ-страница с вложенными панелями имеет высоту около 4561 пикселя даже без загруженных данных.
- Предлагаемое действие: сделать компактное мобильное меню, оставить в первом уровне ключевые разделы и показывать в админке только выбранный рабочий раздел вместо длинной последовательности форм.

### Пустые состояния выглядят как незаполненные панели

- Статус: `ОТКРЫТО`
- Важность: низкая
- Обнаружено: на страницах `Туры`, `Трансферы` и `О лиге` с пустой локальной БД.
- Наблюдение: часть секций остаётся пустыми карточками без сообщения, причины отсутствия данных и следующего доступного действия.
- Предлагаемое действие: добавить компактные пустые состояния с понятным текстом, а недоступные секции не растягивать по высоте.

### Мобильный Safari не входит в текущую браузерную проверку

- Статус: `ОТКРЫТО`
- Важность: средняя
- Обнаружено: при попытке запуска профиля iPhone 13 в Playwright.
- Наблюдение: E2E-конфигурация содержит только Chromium, а локальный WebKit не установлен. Специфичные для iOS Safari проблемы сейчас не проверяются.
- Предлагаемое действие: добавить отдельный Playwright-проект WebKit, установить браузер в CI и включить короткий mobile smoke-набор.
