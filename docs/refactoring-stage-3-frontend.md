# Refactoring Stage 3 Frontend

Дата проверки: 2026-07-27

## Цель этапа

Начать безопасную декомпозицию frontend-кода без изменения пользовательского поведения.

## Что сделано

### API debug logging

- Логика debug-логирования API-запросов вынесена из `web/src/main.js` в `web/src/utils/apiDebugLogger.js`.
- Глобальный monkey-patch `window.fetch` больше не включается по умолчанию.
- Для локальной диагностики логирование включается явно:

```bash
VITE_DEBUG_API_LOGS=true
```

### Router auth guard

- Проверка доступа к маршрутам вынесена из `web/src/router/index.js` в `web/src/router/authGuard.js`.
- `router/index.js` теперь отвечает в основном за декларацию маршрутов, а auth-логика стала отдельным модулем.

### Frontend unit tests

- Подключен Vitest и добавлена единая команда `npm --prefix web test`.
- Auth guard покрыт сценариями публичного маршрута, восстановления сессии и проверки всех ролевых ограничений.
- API debug logger покрыт сценариями выключенного режима, однократной установки, пропуска внешних запросов и маскирования пароля.

### Декомпозиция Admin

- Навигация по разделам вынесена из `Admin.vue` в `components/AdminTabNavigation.vue`.
- Конфигурация вкладок, ролевое ограничение и переходы вынесены в `composables/useAdminTabs.js`.
- Для composable добавлены тесты прав `SUPER_ADMIN`/`REFEREE`, внутренних вкладок и переходов на отдельные страницы.
- Панели игроков, судей, ролей, представителей и блокировок вынесены в `components/admin`.
- State и API-операции игроков, судей и управления доступом вынесены в отдельные тестируемые composables.
- Размер `Admin.vue` уменьшен с 4470 до 3368 строк. Template и script занимают 2572 строки, остальное — стили страницы.
- Крупнейшие оставшиеся зоны ответственности: сезоны, команды и управление турами.

### Декомпозиция Tours

- Сортировка бомбардиров и дисциплинарной статистики вынесена в `composables/useSeasonPlayerStats.js`.
- Composable покрыт тестами фильтрации, сортировки, переключения режима, лимита строк и пустых состояний.
- Таблица, шахматка, playoff-сетка, список туров и статистика вынесены в `components/tours`.
- Вычисления шахматки и playoff-сетки вынесены в `useSeasonMatrix.js` и `useSeasonPlayoff.js`.
- Размер `Tours.vue` уменьшен с 2569 до 1529 строк. Template и script занимают 325 строк, остальное — стили страницы.

### Маршруты и загрузка страниц

- Таблица маршрутов вынесена в `router/routes.js`.
- Всем маршрутам назначены стабильные имена.
- Страницы переведены на ленивую загрузку и больше не входят целиком в стартовый JS-файл.
- Добавлен route smoke-тест уникальности маршрутов, наличия публичных страниц и обязательных auth/role-флагов.

## Почему это первый шаг

Крупные страницы `Admin.vue`, `Tours.vue`, `Match.vue`, `TeamRepDashboard.vue` требуют декомпозиции, но резать их без e2e-тестов рискованно. Этот этап убирает глобальный production-риск и отделяет routing/auth boundary, не трогая сложную бизнес-разметку страниц.

## Команды проверки

```bash
npm --prefix web test

mvn -f app/pom.xml test

```

## Результат проверки

- Frontend production build проходит успешно.
- Frontend: 44 unit- и route smoke-теста проходят успешно.
- Стартовый JS-бандл уменьшен примерно с 404 КБ до 113 КБ; страницы собираются в отдельные чанки.
- Backend `app`: 5 тестов, 0 failures, 0 errors.
- Mailer: 2 теста, 0 failures, 0 errors.

## Статус этапа

Основная декомпозиция `Tours.vue` завершена. `Admin.vue` уменьшен примерно на тысячу строк и разделен по пяти панелям и трем бизнес-workflow, но этап остается открытым до выноса управления сезонами, командами и турами.

Полноценные браузерные e2e-сценарии потребуют тестового окружения с предсказуемыми backend-данными.
