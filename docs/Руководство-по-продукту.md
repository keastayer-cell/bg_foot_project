# Футбол Богородск

Паспорт продукта и руководство по работе с лигой

Версия документа: 1.0
Дата актуальности: 13.09.2026
Основание: рабочая сборка dev от 13.09.2026, включая локальные правки чистых адресов страниц.
Статус: описание реализации; это не подтверждение установки этой сборки на production.

Руководство предназначено для нового владельца проекта, организаторов, судей и представителей команд. Оно объясняет, кто выполняет действия, при каких условиях они доступны и какие последствия возникают. Установка сервера и устройство API описаны отдельно в технической документации.

Числа в примерах условные. Настройки конкретного сезона и Кубка нужно проверять в админке. Загруженный PDF регламента сам по себе не меняет правила расчёта: сроки, лимиты, дисциплину и формат организатор задаёт отдельно.

## 1. Карта продукта и границы данных

### 1.1. Сезон и соревнование

Сезон объединяет команды, судей, сезонные заявки и трансферы. Внутри него могут проводиться Чемпионат и несколько Кубков. В одном сезоне допускается один активный Чемпионат. Для него используются настройки регулярного этапа сезона. Кубок имеет собственные правила и сетку.

Тур принадлежит сезону и конкретному соревнованию. Матч находится внутри тура. Состав на матч и протокол относятся к конкретному матчу. Выбор только сезона не означает, что пользователь выбрал турнир: в разделах с турнирной статистикой нужен также выбор соревнования.

| Объект | К чему относится | Что важно при работе |
|---|---|---|
| Сезонная заявка команды | Сезон | Допуск игроков в сезон не является отдельным согласованием для каждого Кубка |
| Трансфер игрока | Сезон | Переход меняет сезонное назначение игрока, а не только один матч |
| Регулярная таблица | Чемпионат сезона | Кубковые результаты и плей-офф не добавляют очки в регулярную таблицу |
| Кубковая заявка | Конкретный Кубок | Может использовать сезонную заявку либо отдельный список из сезонных игроков |
| Карточки и дисквалификация | Соревнование | Нельзя смешивать остатки наказаний разных турниров |
| Регламент PDF | Конкретное соревнование; возможны старые документы сезона/лиги | Нужно проверять название и область документа |
| Награды и символическая сборная | Конкретное соревнование | Публикуются организатором отдельно от протоколов |
| Ручное оповещение | Выбранная аудитория | Может охватывать всю лигу и не быть привязано к турниру |

### 1.2. Три разных состава

Текущий состав команды - принадлежность игрока к клубу. Сезонная заявка - список игроков, допущенных за клуб в выбранном сезоне. Состав на матч - основной состав и запасные на одну игру. Наличие игрока в профиле клуба не гарантирует, что его можно включить в матч: проверяются сезонная/кубковая заявка и дисквалификация.

Пример: игрок добавлен в клуб, но заявка ещё не одобрена. Представитель должен завершить сезонное оформление. Для Кубка с отдельной заявкой затем нужно включить его и в кубковый список.

### 1.3. Публичные разделы

Посетитель видит сведения о лиге и регламенты, туры и таблицу, игроков, команды, публичные трансферы, дисциплину и опубликованный Зал славы. В профилях доступны спортивные сведения и история. Кабинеты команды и админка требуют соответствующих прав.

В адресах списков сезон и соревнование не показываются. Выбор запоминается в браузере; старые ссылки с параметрами импортируют его и очищаются. Ссылка без параметров не фиксирует турнир для получателя: другой человек увидит собственный сохранённый выбор или доступный вариант по умолчанию.

## 2. Участники и права

### 2.1. Роли

Гость читает публичные данные. Зарегистрированный пользователь получает личный кабинет, избранное и персональную историю уведомлений. Представитель управляет назначенной ему командой. Судья выполняет спортивные и организационные действия. Суперадминистратор дополнительно управляет доступами и исправляет защищённые результаты.

Роль представителя и доступ к команде - разные вещи. Для работы нужны активное назначение команды и разрешения на состав и/или заявку. Пользователь может иметь несколько ролей. Права на команду не означают права на чужой клуб.

| Действие | Пользователь | Представитель | Судья | Суперадмин |
|---|---|---|---|---|
| Публичные сведения | Да | Да | Да | Да |
| Собственный профиль и избранное | Да | Да | Да | Да |
| Состав клуба и состав на матч | Нет | Своя команда, при разрешении на состав | Одна роль судьи не даёт командного доступа | Да |
| Сезонная заявка | Нет | Своя команда, при разрешении на заявку | Проверка и решения по заявкам | Да, включая режим работы за команду |
| Создание сезонов, Кубков, команд и игроков в админке | Нет | Нет | Да | Да |
| Матчи, расписание и публикация туров | Нет | Нет | Да, с ограничениями по статусу | Да, с теми же ограничениями по статусу |
| Заполнение и подтверждение протокола | Нет | Нет | Да | Да |
| Изменение уже подтверждённого протокола | Нет | Нет | Нет | Да |
| Повторное открытие подтверждённого протокола | Нет | Нет | Нет | Да |
| Создание и обработка трансферов | Нет | В пределах своей команды | Да, по всем командам | Да |
| Отзыв одобренного трансфера | Нет | Нет | Нет | Да |
| Ручная корректировка дисквалификации | Нет | Нет | Да | Да |
| Награды, сборная и ручные оповещения | Нет | Нет | Да | Да |
| Роли, назначения команд, сброс пароля другого пользователя | Нет | Нет | Нет | Да |
| Общий журнал действий | Нет | Нет | Нет | Да |

Таблица описывает базовые ограничения реализации. Дополнительные правила доступа могут сузить доступность разделов. Даже суперадминистратор не обходит все бизнес-проверки: например, расписание подтверждённого матча сначала нужно разблокировать открытием протокола.

### 2.2. Назначение представителя

Суперадминистратор находит пользователя, проверяет роль, назначает команду и разрешения. В текущем интерфейсе представителя используется рабочая модель одной команды; сервисы кабинета выбирают первое активное назначение. Не следует оформлять несколько активных команд одному человеку как поддерживаемый сценарий переключения. При смене клуба прежнее назначение нужно снять.

Снятие назначения закрывает командный доступ, но само по себе не удаляет учётную запись и не стирает историю действий. Роль представителя может остаться: наличие одной роли без активной команды недостаточно для кабинета.

Справочник судей и роль судьи в учётной записи тоже не одно и то же. Чтобы назначить конкретного судью в протокол, его запись должна быть привязана к сезону; один судья не может занимать несколько судейских позиций одного матча.

## 3. Подготовка сезона

### 3.1. Последовательность организатора

1. Проверить команды, игроков и судей в справочниках. Устранить дубли и заполнить краткие названия команд.
2. Создать сезон и задать название, статус, число кругов, лимиты игроков, срок заявок и даты трансферного окна.
3. Добавить команды и судей в сезон.
4. Создать Чемпионат внутри сезона, если нужна регулярная таблица. Добавить необходимые Кубки отдельно.
5. Настроить порядок определения мест и наказания за карточки. При необходимости включить плей-офф и матч за третье место.
6. Загрузить PDF регламента для каждого соревнования и сверить его с настройками.
7. Назначить представителей и проверить их доступы.
8. Принять сезонные заявки, затем подготовить и опубликовать матчи.

### 3.2. Статусы и ограничения

Статусы сезона: черновик, активный, закрытый. Отдельный признак активности записи отвечает за её доступность; деактивация и закрытие сезона не равнозначны. Для изменения сезонных игроков и обычных трансферов требуется статус «Активный».

Число кругов не меньше одного. Число туров одного круга: при чётном количестве команд - количество команд минус один; при нечётном - количество команд. Итог умножается на число кругов. При менее чем двух командах регулярных туров нет.

Пример: 10 команд и 2 круга дают 18 туров. Это количество мест в структуре, а не доказательство заполненного расписания. Регулярные туры создаются из структуры Чемпионата; произвольное ручное создание обычного тура не является поддерживаемым способом её построения.

После добавления активных матчей регулярного этапа менять количество кругов и состав участников сезона запрещено. Сначала требуется решить судьбу созданных матчей. При удалении команды из сезона до появления матчей её активные сезонные назначения игроков закрываются.

### 3.3. Что сверять в настройках

| Настройка | Последствие |
|---|---|
| Статус сезона | Открывает или закрывает обычную работу с заявкой и трансферами |
| Срок подачи заявки | Последний календарный день редактирования/подачи включительно; без даты действует ограничение активного сезона |
| Максимум игроков в заявке | Проверяется при добавлении игроков и переходах; отсутствие лимита означает отсутствие этой числовой границы |
| Игроков на поле | Определяет точное число основных игроков в составе матча |
| Даты трансферного окна | Начальная и конечная даты включаются; отсутствие одной даты убирает соответствующую границу |
| Порядок критериев таблицы | Определяет места при равенстве очков |
| Порог ЖК и срок наказания | Задаёт накопительный цикл и число пропусков |
| Срок наказания за КК | Задаёт число пропусков за удаление |
| Плей-офф | Формирует сетку из итоговой регулярной таблицы при завершении этапа |

Сроки заявок и трансферов проверяются по календарной дате сервера. В последний разрешённый день действие ещё доступно. Не следует обещать закрытие по локальному времени пользователя.

## 4. Регламенты

Организатор выбирает сезон, затем соревнование и загружает его PDF. Загрузка заменяет документ выбранного соревнования. Удаление снимает доступность документа. Посетитель ищет нужный регламент в разделе «О лиге» по сезону и турниру.

Сохранившиеся общие документы лиги и сезона считаются отдельными областями, а не автоматически регламентами всех новых Кубков. Перед передачей управления проверить, какие из них ещё актуальны.

Правила из текста PDF не распознаются системой. Если в регламенте написано «пропуск после четырёх ЖК», а в настройках стоит три, автоматический расчёт применит три. Ответственность за согласованность несёт организатор.

При изменении правил в ходе турнира следует зафиксировать решение, обновить документ, проверить настройки и последствия для уже сыгранных матчей. Отдельного механизма версий регламента с датами вступления правил в силу нет.

## 5. Игроки и сезонные заявки

### 5.1. Работа с игроками

Представитель с разрешением на состав создаёт и редактирует игроков своего клуба. Существующего человека нужно находить в справочнике, а не создавать повторно ради перехода. Проверка одинакового имени может заблокировать создание: одно ФИО не является подтверждением личности, поэтому спорные случаи разбирает организатор.

Включение в сезон проверяет принадлежность команде, участие клуба в сезоне, активный статус сезона и лимит. Один игрок не может одновременно иметь активную сезонную заявку за разные команды этого сезона. Переход оформляется отдельным процессом.

### 5.2. Жизненный цикл заявки

Черновик -> Отправлена на проверку -> Одобрена / Возвращена / Отклонена.

Возвращена -> представитель исправляет -> повторно отправлена на проверку.

| Статус | Доступные действия и эффект |
|---|---|
| Черновик | Выбрать игроков, удалить лишних, отправить непустую заявку в срок и в пределах лимита |
| На проверке | Представитель не редактирует; судья или суперадминистратор принимает решение |
| Возвращена | Можно исправить и повторно отправить, пока срок открыт |
| Одобрена | Игроки синхронизируются с активной сезонной заявкой; текущая реализация допускает изменение списка до срока с немедленной синхронизацией |
| Отклонена | Обычного редактирования и повторной отправки из этого статуса нет |

Важно: одобренная заявка не является полностью замороженной. В реализации её можно менять до окончания разрешённого срока без нового цикла одобрения. После срока обычное редактирование блокируется. Это действующее поведение, а не рекомендация организатору обходить проверку.

При отправке требуется хотя бы один выбранный игрок. Одобрение переносит выбранный список в сезонные назначения команды. Решение возможно только по заявке на проверке. Для отклонения обязателен комментарий; при возврате пустой комментарий заменяется текстом «Комментарий не указан».

При добавлении человека, состоящего в другом клубе, дополнительно проверяется трансферное окно и ограничения назначения. Нельзя использовать изменение заявки как гарантированный обход перехода между клубами.

### 5.3. Порядок проверки

1. Открыть очередь заявок с нужным сезоном.
2. Проверить команду, список, лимит и данные игроков.
3. Одобрить корректную заявку; вернуть исправимую; отклонить с объяснением, если допуск невозможен.
4. Проверить, что представитель получил решение и активная сезонная заявка соответствует принятому списку.

## 6. Трансферы

### 6.1. Условия перехода

Представитель принимающей команды выбирает сезон, команду-источник и игрока. Обе команды должны участвовать в сезоне и быть разными. Игрок должен числиться в активной сезонной заявке источника. Окно должно быть открыто, а принимающая команда - иметь свободное место в пределах лимита.

Заявка получает статус «Ожидает решения». Сам запрос ещё не меняет команду игрока. Представитель отдающей команды принимает или отклоняет его. Судья и суперадминистратор могут обрабатывать запросы всех команд.

Наличие ожидающего или уже одобренного трансфера блокирует новый обычный переход того же игрока в этом сезоне. То есть после одного одобренного перехода ещё один обычный переход не предусмотрен. Отклонённые и отозванные запросы сами по себе этой блокировки не создают.

### 6.2. Решения и последствия

| Действие | Кто выполняет | Условия | Последствие |
|---|---|---|---|
| Создать запрос | Принимающая команда; судья; суперадминистратор | Открытое окно, корректные назначения и лимит | Запрос ожидает решения; источник уведомлён |
| Одобрить | Источник; судья; суперадминистратор | Запрос ожидает решения; окно открыто; лимит повторно проверен | Сезонное назначение переносится в новый клуб; обновляется клубная принадлежность |
| Отклонить | Источник; судья; суперадминистратор | Запрос ожидает решения; окно открыто | Команда игрока не меняется; сохраняется решение |
| Отозвать ожидающий | Принимающая команда; суперадминистратор | Запрос ещё ожидает решения | Запрос отозван; окно не проверяется как условие отзыва |
| Отозвать одобренный | Только суперадминистратор | Проверки обратного сезонного назначения и вместимости | Выполняется обратный переход и запрос становится отозванным |

Роль судьи в привилегированном режиме трансферов не даёт права отзыва: в текущем сервисе отзыв зарезервирован за принимающей командой либо суперадминистратором. Подтверждение и отклонение после закрытия окна запрещены даже для привилегированных ролей. Обратный переход проверяет активность сезона и лимит исходного клуба; статус не меняется, если операция не удалась.

Исторические протоколы не переписываются под новый клуб. Отдельная заявка Кубка не является автоматически согласованным трансфером: её состояние нужно проверить отдельно. Дисциплинарные остатки после перехода также требуют внимания организатора - см. раздел 10.

## 7. Матчи и расписание

### 7.1. Подготовка

Судья или суперадминистратор выбирает сезон, соревнование и тур. В матч включаются две разные команды сезона; дата и время обязательны. Назначение матчей в структуре не равнозначно публикации. Пустой тур публиковать нельзя. При первой публикации формируется публичное оповещение.

Для штатной публичной регулярной таблицы должны выполняться два условия: тур опубликован и протокол подтверждён. Поэтому сохранённый результат неопубликованного тура может отсутствовать в таблице.

### 7.2. Статусы расписания

Запланирован - обычная предстоящая игра. Перенесён - изменены дата/время с причиной. Отменён - игра исключена из обычного проведения. Завершён и Технический результат - итоговые статусы, назначаемые подтверждением протокола, а не ручным выбором в редакторе расписания.

При смене даты или времени нужно выбрать «Перенесён». Для переноса и отмены обязательна причина. История изменения расписания сохраняется. На отменённый матч нельзя подать состав или заполнять протокол; отменённая игра не отбывает дисквалификацию.

Расписание подтверждённого матча менять нельзя ни судье, ни суперадминистратору. Сначала суперадминистратор открывает протокол, затем выполняется допустимое изменение. Кнопка расписания для подтверждённой игры заблокирована; ошибка сервера отображается в диалоге без потери введённого текста.

Удалить из тура можно матч только с начальным статусом протокола «Запланирован». Поданные составы и последующие стадии блокируют удаление. Повторное открытие возвращает протокол в «Завершён», поэтому оно не делает удаление автоматически доступным. Удаление разрешённого матча требует подтверждения пользователя.

## 8. Состав на матч и протокол

### 8.1. Состав

Представитель с разрешением на состав подаёт игроков своей команды. Суперадминистратор может сделать это за любую сторону. Роль судьи без дополнительного командного доступа не заменяет это разрешение.

Основных игроков должно быть ровно столько, сколько задано форматом турнира. Запасные добавляются отдельно. Повтор одного игрока в заявке запрещён. В Кубке дополнительно проверяется лимит общего состава на матч. Выбираются только допущенные сезонные/кубковые игроки; дисквалифицированный игрок блокируется с причиной.

Количество игроков на поле влияет на точный основной состав, а не означает, что можно подать любое меньшее число игроков. Если команда не может набрать разрешённый состав, ситуацию решает организатор по регламенту.

### 8.2. Стадии протокола

Запланирован -> Составы поданы -> Идёт матч -> Завершён -> Подтверждён.

Это рабочая последовательность. Реализация не требует обязательного прохождения каждого промежуточного статуса, но для завершения и подтверждения обычного протокола нужны обе заявки на матч.

Судья или суперадминистратор вносит счёт, голы и карточки по игрокам, лучшего игрока матча, судей и примечание. Команда каждой записи должна быть стороной матча; игрок со статистикой должен быть в её составе. Один игрок не может повторяться в протоколе; числовые показатели неотрицательны. Сумма голов игроков каждой команды должна совпасть с итоговым счётом.

При подтверждении обычного результата расписание становится «Завершён». Пересчитывается регулярная таблица, если матч относится к ней; результат становится основанием для статистики и дисциплины. Для Кубка проверяется завершение пары и продвижение победителя. Формируется сохранённый снимок для PDF протокола.

### 8.3. Два исключения

Техническое поражение: можно выбрать только одну проигравшую сторону. Итог фиксируется как 0:3 или 3:0. Обязательно основание в примечании; ненулевая статистика игроков запрещена. Такой результат не создаёт персональных голов бомбардирам.

Протокол только со счётом: суперадминистратор может сохранить результат без ненулевой персональной статистики и без обеих заявок. Это специальное исключение. Оно влияет на командный результат, но не создаёт персональные голы и карточки. Судья такого исключения не имеет.

### 8.4. Исправление

Судья не редактирует уже подтверждённый протокол. Суперадминистратор может исправить его либо повторно открыть. При открытии статус становится «Завершён», удаляется подтверждённый PDF-снимок и пересчитывается таблица. Расписание возвращается к плановому/перенесённому состоянию.

После исправления нужно повторно подтвердить протокол и проверить таблицу, статистику, дисциплину, Кубковую сетку и опубликованные награды. Автоматические письма об исправлении всех этих последствий не гарантируются. Переоткрытие не отзывает ранее прочитанные уведомления; защита от повторной рассылки не означает, что получатель увидел новую редакцию наказания.

PDF отдельного протокола доступен после подтверждения. Организатор может выгрузить архив подтверждённых протоколов сезона. Не следует использовать ранее скачанный PDF как свидетельство актуальности после исправления.

## 9. Таблица, статистика и завершение соревнования

### 9.1. Регулярная таблица

В расчёт входят активные матчи опубликованных туров регулярного этапа с подтверждёнными протоколами и заполненным счётом. Отменённые игры исключены. Матчи Кубка и плей-офф не являются дополнительными матчами регулярной таблицы.

Таблица содержит сыгранные игры, победы, ничьи, поражения, забитые и пропущенные голы, разницу и очки. По умолчанию победа даёт 3 очка, ничья - 1, поражение - 0. Начисление определяется конфигурацией таблицы; перед сезоном следует сверить фактические значения. Места сначала определяются по очкам. Порядок дополнительных критериев настраивается; в конце используется алфавит.

Поддержаны разница голов, забитые голы, победы, личные встречи, меньше пропущенных голов, выездные победы и голы, дисциплинарные баллы. Личные встречи рассматриваются как мини-таблица между командами с равными предыдущими показателями. Дисциплинарные баллы: ЖК даёт 1, КК/удаление за вторую ЖК - 3; меньше баллов лучше.

Порядок по умолчанию: очки, разница голов, забитые голы, алфавит. Изменение порядка критериев может изменить места уже после сыгранных матчей; текст регламента нужно поддерживать согласованным.

### 9.2. Персональная статистика

Голы и карточки считаются по событиям подтверждённых протоколов в выбранном соревновании. Неподтверждённый протокол не является основанием итоговой статистики. При смене клуба игрок остаётся одним человеком в статистике; у него могут отображаться несколько команд.

Текущий основной набор персональных показателей - голы, ЖК и КК. Не следует обещать полноценный автоматический учёт ассистов, сейвов и других показателей, которых нет в штатном вводе протокола. Для ручной номинации организатор может использовать собственное решение, но оно не превращает показатель в автоматически рассчитываемую статистику.

### 9.3. Завершение регулярного этапа и плей-офф

Для завершения нужны активные регулярные туры, хотя бы один матч и подтверждение всех активных матчей регулярки. Неподтверждённая игра блокирует завершение. Пустые туры при завершении деактивируются; непустые публикуются. Таблица пересчитывается.

Если плей-офф включён, состав сетки берётся из итоговой таблицы. Число команд - степень двойки, не меньше двух и не больше доступных участников. Матч за третье место требует минимум четырёх участников плей-офф. Сетка формируется один раз; повторное формирование блокируется.

Завершение Чемпионата не должно закрывать сезон-контейнер, пока продолжаются Кубки. Для окончания всей программы сезона организатор отдельно проверяет соревнования и переводит сезон в закрытый статус. Сетка и подготовленные места в плей-офф не являются автоматическим доказательством назначения всех дат и заполнения всех результатов.

## 10. Дисциплина

### 10.1. Автоматическое наказание

Основание - карточки подтверждённого протокола. Для Чемпионата применяются дисциплинарные настройки сезона/его таблицы; для Кубка - собственные настройки Кубка. Порог ЖК и длина пропуска проверяются отдельно. Нулевой порог ЖК отключает накопительный пропуск, но не удаляет карточки из статистики.

Пример: порог 3 ЖК, наказание 1 матч. Игрок получает по одной ЖК в трёх подтверждённых играх. После третьей возникает пропуск следующего учитываемого матча этого турнира. После достижения порога цикл ЖК уменьшается на порог; новые карточки могут создать новый цикл наказания.

КК или удаление за вторую ЖК создаёт наказание по настройке КК. В Чемпионате КК сбрасывает накопительный цикл ЖК, и ЖК этого матча не добавляются в него. В Кубке ЖК и КК учитываются независимо; в одной игре возможно сложение наказаний. Это различие заложено в расчёт.

### 10.2. Как отбывается пропуск

Матчи рассматриваются по дате/времени начала, при совпадении - по порядку записей. Остаток уменьшается на подтверждённых активных неотменённых матчах соответствующей команды в этом соревновании. Просто наступившая дата, будущая игра, перенос и неподтверждённый результат пропуск не отбывают. Сам матч, вызвавший наказание, новый пропуск не погашает.

Технический подтверждённый результат не исключён из этого правила: если он соответствует обычным условиям учёта матча, остаток может уменьшиться. Публикация тура не является условием дисциплинарного расчёта так же, как для регулярной таблицы.

### 10.3. Просмотр и корректировка

Дисциплинарный центр показывает карточки, действующие остатки, близость к порогу, матч-основание и решения организатора. Судья или суперадминистратор может установить новый неотрицательный остаток с понятной причиной не короче пяти символов. Новый остаток заменяет текущую величину, а не прибавляется к ней как число дополнительных матчей.

Устанавливая 0, организатор снимает оставшийся пропуск. Корректировка сохраняет автора, время, старое/новое значение и причину; представители выбранной команды уведомляются. Решение не удаляет карточки из спортивной статистики. Его действие учитывается по времени решения, поэтому оно не является произвольным изменением задним числом любого старого матча.

### 10.4. Ограничения, требующие внимания

В Чемпионате центр учитывает ручные корректировки при проверке допуска. Кубковая проверка состава использует отдельный автоматический расчёт карточек: ручное решение центра не подключено к нему одинаковым способом. После ручного снятия кубкового наказания игрок может оставаться заблокированным в форме состава. Такой случай требует устранения расхождения, а не повторного назначения фиктивного наказания.

В основном расчёте остаток связан с командой, указанной в карточке или последней корректировке; обычный трансфер сам по себе не переносит эту связь автоматически на новый клуб. После перехода дисквалифицированного игрока организатор должен сверить допуск и остаток. Это ограничение реализации, а не правило, разрешающее избегать наказания через переход.

Исправления протоколов и изменение дат могут менять хронологический расчёт. Проверка состава в момент подачи не заменяет повторную проверку после изменения оснований дисциплины.

## 11. Кубки

Организатор создаёт Кубок внутри сезона, выбирает команды сезона, формат состава, число матчей в паре, отдельные правила финала и третьего места, дополнительное время/пенальти и дисциплину. Минимум для жеребьёвки - две команды.

### 11.1. Режим заявки

Общая сезонная заявка: доступные игроки берутся из сезонных назначений команд. Отдельная заявка: организатор или представитель с доступом к заявке выбирает собственный список Кубка, но только из игроков этой команды в сезоне. Проверяется кубковый лимит. Отдельный список не является способом заявить постороннего игрока без сезона.

### 11.2. Сетка и пары

1. Выбрать участников и настройки до утверждения сетки.
2. Провести жеребьёвку или задать ручную расстановку всех участников ровно по одному разу.
3. Проверить пары и утвердить сетку. После утверждения основные правила Кубка блокируются.
4. Для пары с определившимися участниками указать даты всех её матчей. Повторно создать матчи уже назначенной пары нельзя.
5. Заполнить и подтвердить протоколы, затем проверить продвижение победителей.

Победитель пары определяется после подтверждения всех её матчей по общему счёту. При двух матчах стороны меняются; сумма приводится к исходным участникам пары. Победитель и, для третьего места, проигравший передаются в связанные следующие пары.

При равной сумме счёта ручное определение победителя доступно через включённую серию пенальти: вводится неравный неотрицательный счёт серии. Серия сама собой не рассчитывается. Настройка дополнительного времени не является автоматической симуляцией его результата. Если включено только дополнительное время и после введённых результатов остаётся ничья, штатная операция выбора победителя по пенальти недоступна: это ограничение нужно учитывать до утверждения сетки.

При исправлении уже подтверждённого кубкового результата следует отдельно проверить следующие пары. Безопасный автоматический откат всех последующих матчей не гарантирован.

## 12. Зал славы

### 12.1. Награды

Судья или суперадминистратор выбирает сезон и соревнование, настраивает названия номинаций, выбирает победителей и сохраняет. Командная награда допускает участника соревнования. Игрок выбирается из доступного списка заявки соревнования; этот список не означает доказанное участие хотя бы в одном сыгранном матче.

Чемпион, серебряный и бронзовый призёры - ручной выбор организатора. Они не назначаются автоматически только потому, что таблица готова. Лучший игрок, вратарь, защитник, полузащитник и другие номинации также являются решением организатора.

Лучший бомбардир рассчитывается при сохранении наград по максимальному числу голов в подтверждённых протоколах выбранного соревнования. При равенстве положительного максимума награда создаётся каждому лидеру. Если никто не забил, такой награды нет. После исправления результатов нужно вновь сохранить награды: публичная запись не пересчитывается непрерывно при каждом открытии Зала славы.

### 12.2. Символическая сборная

Организатор задаёт схему, выбирает игроков и позиции. Формат турнира определяет предлагаемые варианты для 5, 11 и других размеров состава. Игрок не может занимать две позиции одной сборной. Схема и размещение являются редакторским выбором, а не автоматическим подбором по статистике.

Реализация сохраняет выбранные позиции и координаты, но не гарантирует серверной проверки полного количества игроков и соответствия каждого амплуа схеме. Перед публикацией нужно визуально проверить состав, наличие вратаря и правильное число игроков.

Публичный Зал славы показывает только опубликованные записи. Сохранить и опубликовать - разные решения. Имена и командные названия сохраняются как снимки награждения; фотография берётся из текущего профиля игрока. Если фотографии нет, используется заглушка. Игроки и команды доступны по ссылкам; переход из Зала славы сохраняет источник для возврата.

Награды сейчас относятся к соревнованию в целом. Название «Сборная тура» в оформлении само по себе не создаёт отдельных наград для каждого тура. Отдельная независимая сущность награждения тура не реализована.

## 13. Оповещения и почта

### 13.1. Каналы и состояние

Колокольчик и email - два канала. Наличие сообщения на сайте не доказывает отправку письма. Шаблон и настройки определяют доставку; при технической неудаче письмо может быть отправлено позже после повторной попытки.

История колокольчика показывает сообщения постранично по 10. В компактной строке - краткая информация; полный текст раскрывается при открытии. Открытие отмечает прочтение, а «Ознакомился» - отдельное явное подтверждение. Прочитано не означает ознакомление и не означает выполненное бизнес-действие. Подтверждение уведомления о трансфере не одобряет сам трансфер.

Прочтение и ознакомление не удаляют запись. Сообщение с истёкшим сроком действия перестаёт попадать в выдачу. Гость видит публичные сообщения, но персональные статусы прочтения ему не сохраняются.

### 13.2. Основные события

| Событие | Кому | Каналы и особенности |
|---|---|---|
| Начало/закрытие сезона | Зарегистрированным пользователям; публично гостям | Колокольчик и email |
| Первая публикация тура | Зарегистрированным пользователям; публично гостям | Колокольчик; штатного email нет |
| Заявка отправлена на проверку | Активным судьям | Колокольчик и email; требуется внимание |
| Решение по заявке | Представителю, указанному в заявке | Колокольчик и email |
| Новый запрос на переход | Представителям источника, кроме инициатора | Колокольчик и email |
| Решение/отзыв трансфера | Инициатору и представителям обеих сторон, кроме автора решения | Колокольчик и email |
| Дисквалификация за ЖК/КК | Активным представителям команды игрока | Колокольчик и email, ссылка на вызвавший наказание матч |
| Перенос/отмена матча | Представителям команд | По активному шаблону события расписания |
| Корректировка дисквалификации | Представителям указанной команды | По активному шаблону корректировки, с новым остатком и причиной |
| Регистрация, восстановление пароля, выдача отдельных ролей | Владельцу учётной записи | Email |

Обычная ЖК ниже порога не создаёт сообщения о дисквалификации. При подтверждении протокола наказание каждого игрока создаёт отдельное событие. Повторная доставка того же вида наказания тому же игроку по одному матчу защищена от дублей. Прямое редактирование уже подтверждённого протокола не является повторным первым подтверждением и не гарантирует новое письмо.

### 13.3. Настройки и ручные сообщения

Пользователь отдельно настраивает колокольчик и email по категориям событий. По умолчанию каналы включены. Сообщения, требующие решения или подтверждения, и письма безопасности обходят отключение обычной категории. Выключить необязательную рассылку не означает скрыть обязанности представителя.

Организатор может создать ручное сообщение с заголовком, кратким и полным текстом, важностью, аудиторией и требованием ознакомления. Ручные сообщения в текущем сценарии не отправляются email автоматически. В истории рассылок доступны охват, прочтение и ознакомление; эти счётчики описывают доставку/просмотр, а не выполнение действия на поле или решение заявки.

Шаблоны можно отключить или изменить. Если ожидаемого сообщения нет, нужно проверить получателя, активное назначение команды, шаблон, сроки и канал. В сезонных заявках доставка даже в колокольчик сейчас связана с наличием email у адресата; это известное ограничение. Адреса представителей и судей следует заполнить до запуска сезона.

## 14. Личный кабинет, сводка и журнал

### 14.1. Личный кабинет

Пользователь изменяет свои данные, смотрит роли и командные назначения, выбирает каналы уведомлений, хранит избранные команды/игроков и управляет паролем. Избранное относится к учётной записи и не даёт дополнительных полномочий.

Смена пароля требует проверки текущего пароля. Восстановление использует одноразовую ссылку с ограниченным сроком действия. Суперадминистратор может инициировать восстановление другого пользователя; это не означает просмотр его старого пароля. Выход со всех устройств завершает сессии, включая текущую.

Экран «Активные сеансы» сейчас не является полным списком устройств с отдельным отзывом каждого. Полноценная деактивация учётной записи описана как предложение в отдельном документе, но не реализована как готовая функция продукта.

### 14.2. Административная сводка

Сначала выбираются сезон и соревнование. Турнирный блок содержит неподтверждённые протоколы, проблемы составов, непубликованные туры, неполные заявки и действующие дисквалификации. Неподтверждённые протоколы считаются для уже наступивших игр опубликованных туров. Ближайшие матчи без двух составов - для предстоящих семи дней. Неполная заявка означает число игроков меньше формата на поле, а не проверку всех данных анкеты. Задачи неполных заявок и обязательных оповещений доступны в сводке суперадминистратора. Блок сезона содержит заявки на проверке и трансферы, потому что они не относятся только к одному Кубку. Обязательные сообщения без ознакомления относятся ко всей лиге.

Счётчики являются текущим срезом, а не отчётом за произвольный период и не количеством нарушений регламента. Ссылка из задачи ведёт к рабочему разделу с соответствующим контекстом. Ноль означает отсутствие задач по этому критерию, но не подтверждение готовности всего сезона.

### 14.3. Журнал действий

Доступен суперадминистратору. Фиксирует поддержанные значимые изменения: автор, время, раздел, действие, безопасные значения до/после. Запись появляется после успешного сохранения; отклонённая операция не считается выполненным изменением. Если данные не изменились, отдельная запись может не создаваться.

Это журнал отдельных бизнес-действий, а не запись всех кликов, просмотров и попыток входа. Он не восстанавливает события до своего внедрения и не показывает секреты. Фильтр «Раздел» означает тип объекта, например матч или заявка; даты охватывают календарные дни целиком. Отсутствие записи не следует трактовать как доказательство отсутствия любого действия вне охвата журнала.

## 15. Типовые проблемы и порядок решения

| Ситуация | Что проверить | Кто решает |
|---|---|---|
| Игрок не виден в составе матча | Сезонное назначение, кубковый режим заявки, команда, дисциплина | Представитель и организатор |
| Нельзя отправить заявку | Статус, срок, непустой список, лимит | Представитель; настройки проверяет организатор |
| Нельзя подтвердить протокол | Обе заявки, сумма голов, игроки состава, техническое основание | Судья; специальные исключения - суперадминистратор |
| Результат есть, а таблица не изменилась | Подтверждение, публикация тура, регулярный этап, выбранное соревнование | Судья/суперадминистратор |
| Нельзя изменить расписание | Подтверждённый протокол; допустимый статус и причина | Протокол открывает суперадминистратор |
| Нельзя удалить матч | Протокол уже не начальный; есть составы/дальнейшие стадии | Организатор выбирает исправление вместо удаления |
| Нельзя создать/обработать трансфер | Активный сезон, окно, лимит, назначение игрока, прежний переход | Источник/организатор в рамках прав |
| Нужно отменить одобренный переход | Активность сезона, обратный лимит и последствия заявок | Только суперадминистратор |
| Карточку указали неверно | Исправить основание в протоколе, затем перепроверить остаток | Суперадминистратор |
| Награда бомбардира устарела | Исправлены протоколы после последнего сохранения наград | Судья/суперадминистратор сохраняет награды повторно |
| Нет уведомления | Получатель, email, активное назначение, шаблон, настройки, срок | Организатор; доставку проверяет сопровождающий |
| Получатель ссылки видит другой турнир | Чистая ссылка не переносит локальный выбор | Получатель выбирает сезон и турнир в фильтрах |

После исправления результата использовать один порядок: протокол -> таблица и статистика -> дисциплина и допуск -> зависимые пары -> награды -> информирование заинтересованных команд. Это контроль организатора, а не обещание автоматической рассылки на каждом шаге.

## 16. Передача управления и актуализация

### 16.1. Проверка при передаче

1. Назначить нового суперадминистратора и проверить вход с его учётной записью.
2. Проверить активные роли и назначения представителей, убрать устаревшие командные доступы.
3. Передать перечень текущих сезонов/соревнований, ответственных судей, сроки и незавершённые задачи.
4. Сверить регламенты с настройками, сезонные и кубковые заявки, действующие наказания и историю корректировок.
5. Проверить неподтверждённые матчи, расписание и спорные результаты. Отдельно проверить пары Кубка после исправлений.
6. Проверить email адресатов, шаблоны, обязательные сообщения и фактическую доставку контрольного события без массовой тестовой рассылки.
7. Сверить опубликованные награды и сборные с итогами турниров.
8. Передать это руководство, журнал релизов и отдельно техническую инструкцию сопровождения. Секреты передаются отдельным защищённым способом.

### 16.2. Чего не считать готовыми возможностями

В реализации есть заготовки общего поиска и календаря, но они не подключены как полноценные публичные разделы текущего маршрутизатора. Их наличие в исходниках и плане не означает доступность посетителю. Полная деактивация аккаунта, награды отдельно за каждый тур, версии правил с датой вступления и полный список устройств также не описываются здесь как реализованные функции.

Особого контроля требуют ручные кубковые корректировки дисциплины, наказания после трансфера и откат последующих кубковых пар. Эти ограничения перечислены, чтобы новый владелец мог отличить правило продукта от расхождения реализации.

### 16.3. Обновление при каждом релизе

Редактируемый первоисточник - этот Markdown. PDF собирается из него; вручную менять только PDF нельзя. При изменении прав, условий, статусов, расчётов, уведомлений или пользовательского процесса обновляются соответствующие разделы, версия документа, дата и основание сборки. Затем PDF пересобирается и визуально проверяется.

При чисто визуальном изменении без новых правил нужно проверить, не устарели ли названия и описание действий. Если руководство не требует правки, это явно отмечается в записи релиза. Таким образом каждый релиз проходит проверку документа, но не порождает формальное переписывание неизменных правил.

Автоматическая сборка PDF обеспечивает единый текст, но не извлекает бизнес-смысл из кода. За содержательную сверку отвечает автор изменения. Перед выпуском в test/production нужно проверить, что версия руководства соответствует именно публикуемой сборке.
